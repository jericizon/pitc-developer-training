# Stockroom

Stockroom is a small product inventory manager. You can add, edit, and delete products, see stock totals, search and filter the table, and mark products as favorites. It is an Express.js learning project. This folder is the JSON API; the UI is the Next.js app in `nextjs-dashboard/`.

## Technology Stack

- **Backend:** Node.js, Express.js 5, CommonJS modules, in-memory product array
- **Frontend:** the Next.js app in `nextjs-dashboard/` (React, TypeScript)
- **Browser APIs:** Web Storage API (`localStorage`) and Constraint Validation API, used by the Next.js app
- **Package manager:** pnpm

## Prerequisites

- Node.js 20.12 or newer (check with `node -v`)
- pnpm (check with `pnpm -v`)

## Getting Started

1. Install dependencies:

   ```bash
   pnpm install
   ```

2. Start the development server, which restarts when files change:

   ```bash
   pnpm dev
   ```

3. Open `http://localhost:3001/` to see the JSON home response. The UI runs from the Next.js app, not from this server.

For a normal start without auto-restart, run `pnpm start`. Stop the server with `Ctrl+C`. Run the automated tests with `pnpm test`.

## Configuration

### Port

The server uses port 3001 by default. To change it, create a `.env` file in the project root. It is git-ignored.

```text
PORT=3002
```

A `PORT` value set in the shell takes priority over `.env`, for example `PORT=3002 pnpm dev`.

## Using the API

This server returns JSON only. The UI is the Next.js app in `nextjs-dashboard/`; `pnpm dev` from the repo root starts both, and the UI is at http://localhost:3000/ by default. Call the endpoints below directly, or import the Postman collection.

## Troubleshooting

- **`EADDRINUSE` on startup:** Another program is using the port. Set a different `PORT` (see Configuration).
- **Products are gone after a restart:** This is expected. Products live in memory only.
- **Favorites differ between browsers:** Favorites are stored per browser, not on the server.
- **`pnpm: command not found`:** Install pnpm before running the commands above.

## API Documentation

Base URL: `http://localhost:3001`

Responses use one of two shapes:

```json
{ "success": true, "data": { "id": "1", "name": "Wireless Mouse" } }
```

```json
{ "success": false, "message": "Product not found" }
```

### Product fields

| Field      | Type    | Rules                                             |
| ---------- | ------- | ------------------------------------------------- |
| `id`       | string  | Generated by the server                           |
| `name`     | string  | Required, 1–100 characters                        |
| `sku`      | string  | Required, 3–20 letters, numbers, or hyphens, unique (case-insensitive) |
| `category` | string  | Required, 1–50 characters                         |
| `price`    | number  | Required, 0 or more                               |
| `quantity` | integer | Required, 0 or more                               |

Every product returned by the API also includes `status`, computed from `quantity`:

| Quantity | Status         |
| -------- | -------------- |
| 0        | `out-of-stock` |
| 1–5      | `low-stock`    |
| 6 or more | `in-stock`    |

### GET /products

Returns all products. Optional query parameters:

| Parameter  | Description                                                    |
| ---------- | -------------------------------------------------------------- |
| `search`   | Matches part of the name or SKU, case-insensitive             |
| `category` | Matches the category, case-insensitive                        |
| `status`   | `in-stock`, `low-stock`, or `out-of-stock`                    |

Example: `GET /products?search=mouse&status=in-stock`

- `200` with an array in `data`
- `400` if `status` is not one of the allowed values

### GET /products/:id

- `200` with the product in `data`
- `404` if the product does not exist

### POST /products

Request body (JSON):

```json
{ "name": "Wireless Mouse", "sku": "ACC-010", "category": "Accessories", "price": 599, "quantity": 25 }
```

- `201` with the created product, including its new `id`
- `400` with a message describing the invalid fields
- `409` with `"SKU already exists"` if the SKU is taken

### PUT /products/:id

Send all product fields. The body uses the same rules as POST.

- `200` with the updated product
- `400` for invalid input
- `404` if the product does not exist
- `409` if the SKU belongs to another product

### DELETE /products/:id

- `200` with `{ "success": true, "data": { "id": "1" } }`
- `404` if the product does not exist

### GET /activity

Returns the latest 50 product changes, newest first. Each entry has `id`, `action` (`created`, `updated`, or `deleted`), `productId`, `productName`, `detail` (for example `quantity 25 → 24`, or `null` for deletes), and `at` (ISO time). The log is in memory and resets on restart.

- `200` with an array in `data`

### Errors

Malformed JSON returns `400` with `"Malformed JSON request body"`. Unknown routes return `404`. Unexpected server errors return `500` with a generic message; details are written to the server console only.

## Browser API Implementation

The browser code now lives in the Next.js app (`nextjs-dashboard/app/stockroom/`). The behavior below still applies to the UI.

### Web Storage API

Favorite product IDs are stored as a JSON array under the `stockroom.favorites` key in `localStorage`, so they survive a page refresh. When products load, IDs that no longer match a product are removed. Favorites are stored per browser and are not sent to the server.

### Constraint Validation API

The product form uses native attributes: `required`, `min`, `step`, and `pattern` on the SKU (`[A-Za-z0-9\-]{3,20}`). The submit handler calls `checkValidity()` and `reportValidity()` before sending anything. When the server reports a duplicate SKU, the handler sets a custom message with `setCustomValidity()` and shows it with `reportValidity()`. The message clears when the SKU changes. The server validates the same rules, so the frontend checks are not the only protection.

## Postman Testing

1. In Postman, choose **Import** and select `postman/Stockroom.postman_collection.json`.
2. The collection variable `baseUrl` is `http://localhost:3001`. Change it if your server uses another port.
3. Start the server, then run the requests in order. **Create product** stores the new ID in `productId`, which the Update and Delete requests use.
4. Each request's description lists the expected responses.

## Error Handling

Every API error uses the same format:

```json
{ "success": false, "message": "SKU already exists" }
```

| Status | When |
| --- | --- |
| 400 | Invalid input, malformed JSON, or an unknown `status` filter |
| 404 | Product ID not found, or unknown route |
| 409 | SKU already used by another product |
| 413 | Request body larger than 100 KB |
| 500 | Unexpected server error. The details are logged on the server, not returned |

- Every create and update is validated on the server before any data changes, so a rejected request never leaves a partial product.
- Retrying a `POST` with the same SKU returns 409 instead of creating a duplicate.
- Every response includes an `X-Request-Id` header, and the server log lines for that request include the same ID.
- Browser requests to the API time out after 10 seconds and show a message.
- Not applied, because this MVP has no equivalent: automatic retries (no external services), dead-letter queues (no queues), alerts (no alert channel is configured), and rate limiting (no authentication). Add these before any public deployment.

## Known Limitations

- Products are stored in memory and reset when the server restarts.
- Favorites are stored in each browser's `localStorage`. They are not shared between browsers and are not tied to a user.
- There is no authentication, pagination, or database.
